<goal>MCP tool responses must emit Cyrillic and angle brackets as literal characters instead of \uXXXX escapes. Field measurement: planning_read_feature on 007-2-submodule-workflow-finish returned 74 588 chars of which 11 011 are escape sequences — real text 19 648 chars, ×3.8 bloat. Responses overflow MCP client output limits and get dumped to files.</goal>
<context>Source: FEATURELIST/overmind-features-2026-09-23.md OM-1, DMT field run 2026-09-23 (main agent + 5 parallel sonnet agents, latest build pulled and rebuilt before the run). Escaping originates from System.Text.Json's default HTML-safe JavaScriptEncoder in the JSON-RPC envelope serialized by the ModelContextProtocol SDK inside src/Overmind.Mcp. OvermindApiClient deserialization is not the source. This feature was drafted pre-measurement with a ~25-30% estimate; the field number is 3.8x on Cyrillic payloads — the field data is the contract.</context>
<scope>Locate McpServer construction / JSON-RPC serializer options in src/Overmind.Mcp (Program.cs / registration) and set Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping on the options used for tool payload serialization. Verify representative tools: planning_list_features, planning_read_feature, planning_read_artifact (sections), list_entries, search.</scope>
<anti-scope>No changes to OvermindApiClient request/response parsing. No output reformatting or trimming. No new tools.</anti-scope>
<constraints>JSON must stay valid: quotes, backslashes and control characters remain escaped. UnsafeRelaxedJsonEscaping is acceptable because the consumer is an MCP client, not an HTML page. The MCP SDK may serialize with its own options — if they are not exposed, find the SDK's supported extension point instead of forking serialization.</constraints>
