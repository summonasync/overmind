<goal>
Priority survives the disk round-trip: feature.md frontmatter carries `priority: p1`, the importer parses it back, and missing/unknown values downgrade visibly to P2 with a report line.
</goal>

<context>
The materializer (src/Overmind.Infrastructure/Planning/PlanningMaterializer.cs, feature-file rendering) and importer (BacklogImporter / feature.md frontmatter parsing) already round-trip fields like status via frontmatter — priority joins them. The 033 clobber guard means the regenerated files respect local edits; the frontmatter addition changes every feature.md's bytes once (expected diff, not drift — the row hashes refresh on the next materialize cycle by design).
</context>

<scope>
- Materializer: emit `priority: pN` in feature.md frontmatter (position consistent with existing keys).
- Importer: parse `priority:` — valid lowercase p0..p3 maps to the enum; missing or unknown value → P2 + one report/warning line (visible downgrade, never silent); case-insensitive parse accepted.
- Tests: round-trip both directions (create p1 → materialize → frontmatter shows priority: p1 → wipe-and-import → priority preserved); unknown value (priority: urgent) → P2 + report line; missing key → P2, no warning noise beyond the accepted shape; byte-stability: second materialize without board changes is byte-identical.
</scope>

</anti-scope>
