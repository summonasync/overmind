# Feature 039 — Artifact patch write: append `<log>` / replace XML-секции / tick AC — без перезаливки тела

<goal>
Частичная запись артефактов: правка одной секции стоит как правка одной секции, а не как перезаливка документа целиком. Сегодня единица записи у `planning_upsert_artifact` — полное тело, поэтому каждое однострочное дополнение в `<log>` задачи пересылает 13–20 KB через контекст агента (выходные токены, которые дороже входных). Это названо единственным крупнейшим источником токен-стоимости тремя из четырёх авторов полевого фидбека — и именно оно схлопывает разницу «файлы vs Overmind» почти полностью.
</goal>

<requirements>
- Append в `<log>` артефакта без отправки тела — самая частая операция воркфлоу (каждый исполнитель после каждого шага), сейчас самая дорогая.
- Replace ровно одной XML-секции (`<obstacles>`, `<acceptance-criteria>`, …) без пересылки остальных.
- Отметка пункта acceptance-criteria выполненным по индексу или по тексту.
- Версия артефакта инкрементируется, лог отражает вид патч-операции (что и куда дописано/заменено).
- Патч несуществующей секции/индекса — явная ошибка, не молчаливое создание.
- Эхо мутации компактное — наследует контракт 037-mcp-echo-slimming, полное тело не возвращается.
- Материализация корректно отражает патч в `BACKLOG/`-файлах (не ломает clobber guard 033).
</requirements>

<non-goals>
- Частичное чтение (`sections`, read-by-id) — отдельная фича 040.
- Diff между версиями артефакта — вторая волна полевого фидбека.
- Batch-патчи нескольких артефактов одним вызовом — вторая волна.
- Generic JSON-Patch/RFC-6902 формат — нужны три конкретные операции, не универсальный протокол.
</non-goals>
