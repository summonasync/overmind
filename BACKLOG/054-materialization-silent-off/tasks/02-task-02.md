<goal>A fresh project either materializes out of the box, or onboard says explicitly that the mirror is off and how to turn it on — and the quickstart stops overpromising.</goal>
<context>Default planning.materializationDefault=off (SettingDefaults) + per-project override exists (Project.PlanningMaterialization != Inherit). The quickstart claims "the BACKLOG/ tree under the project root is rewritten after every planning mutation" — true only when strategy is on. Field agents on a fresh DMT install expected the mirror and got silence. DECISION REQUIRED from the user: flip the global default to on (target model: mirror out of the box; 033 clobber guard already protects local edits) vs keep off + a prominent one-step enable path in the onboard trigger line.</context>
<scope>Implement the chosen default; qualify the quickstart sentence for the off strategy; if default stays off, the onboard trigger line must name the exact enable action (settings key or UI path).</scope>
<anti-scope>Do not remove the per-project override or the archive strategy. No new MCP tools.</anti-scope>
<constraints>User must sign off on the default flip before it ships — it changes disk-writing behavior for every fresh install.</constraints>
