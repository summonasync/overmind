# Feature 041 — Entries listing: `list_entries` отдаёт метаданные по умолчанию, тела — по явному флагу

<goal>
`list_entries` сегодня возвращает полные тела всех записей: на девяти коротких заметках это 56 831 символ одной строкой, отрезанный клиентом по токен-лимиту — «посмотреть, что вообще есть в проекте» стоит столько же, сколько прочитать проект целиком. Это первое, обо что спотыкается агент (первый же обзорный вызов, ещё до любой работы), и самое дешёвое из трёх проявлений гранулярности в починке.
</goal>

<requirements>
- Дефолт `list_entries` — только метаданные: `id`, `title`, `type`, `tags`, `updatedAt`, размер тела.
- Полное содержимое — через `read_entry` по id либо явный флаг `include_content: true`.
- Лимиты, порядок и пагинация `list_entries` описаны в описании тула (при девяти заметках вопрос не встал, при сотне — встанет).
</requirements>

<non-goals>
- Партиал-чтение артефактов планирования (spec/plan/task) — 040; 041 только про entries-листинг.
- Web UI — листинг в UI уже другой.
</non-goals>
