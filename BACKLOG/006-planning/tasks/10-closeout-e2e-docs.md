E2E dogfood (script it as a repeatable set of shell steps recorded in this file's `<log>`, not as a committed test):
1. Start the Host with a temp `Overmind:DatabasePath`, `--no-tray`, and a temp web root.
2. Register a project whose `DiskPath` is a temp copy of this repo (or at least of `BACKLOG/` + `BACKLOG.md`).
3. Run `--import-backlog <copy>` → verify R7 spot-checks against the source files: feature statuses and versions, `spec.md` `FrozenAt` from the `validated:` date, task `Order` from `NN-` prefixes, `<log>` lines preserved verbatim, `review:` levels (006/01 = hard, 006/03 = light), `requirements.md` ignored.

5. Edit a materialized file by hand → `GET .../planning/drift` reports `Modified` → `POST .../materialize` `{force:false}` → 409 → `{force:true}` → clean drift.
6. Drive one task through the agent door: `current` → `set_status in_progress` → `append_log` → `set_status done`; verify the board counters move.

9. Run the real MCP adapter (`overmind-mcp`) against this Host and list tools/resources; call `planning_current_task` and read `overmind://projects/{id}/planning/features` to confirm the rendered markdown.

<obstacles>
- **Step 5 task text vs built semantics (no code change):** the task expected `materialize {force:false}` → 409 after a hand edit of a *tracked* file; the implementation (006/05 scope "tracked paths are rewritten freely", pinned by `PlanningMaterializationTests`) gates `force` on FOREIGN untracked files only. Observed: hand edit → drift `modified`; `force:false` → 200, file rewritten, drift clean. The 409→force→clean dance itself was proven in step 4 (initial adoption of the copy's untracked originals). Changing this to 409-on-drift would be a product decision altering 006/05 semantics and tests — recorded, not "fixed".
- **e2e nit 1 — `archive → off` orphans the archive root's `BACKLOG.md`.** `ClearAsync` locates the tracked index file repo-path-first (`LocateTrackedFile` checks DiskPath before the archive root), removes the block from the repo copy, and drops the row — the archive copy of `BACKLOG.md` is never deleted and nothing will clean it later (its row is gone). Cosmetic (internal data dir, derived cache) but strictly violates 006/05 AC "off removes tracked files" for this one path. → `BACKLOG.md` Deferred (source 006/10).
- **e2e nit 2 — task filenames do not round-trip.** The importer takes `Order` from the `NN-` prefix but does not store the filename slug; the materializer regenerates the slug from the task's H1 (`# 006/05 — …` → `05-006-05-planning-materialization-off-on-archive.md`). Materializing `on` over an imported repo therefore writes new-named task files and leaves the hand-named originals as untracked duplicates (observed: 23 new names, 24 original task files + `01b` left behind, incl. `075-uri-scheme-rename`'s order-75 name). → Deferred.
- **e2e nit 3 — materialized `feature.md` duplicates the H1.** The importer keeps the body's `# Feature NNN — …` heading inside `Body` (title is read, not stripped), while the materializer prepends its own heading. Only bites on import→materialize round-trips of this corpus (UI/MCP-created bodies don't start with that heading). → Deferred.
- **e2e nit 4 — legacy status values default silently.** 001's spec/plan carry `status: approved` (pre-006 vocabulary) → imported as `draft` + a Skipped note. Declared importer behavior, but the corpus predates the vocabulary — decide whether legacy values (`approved`) map to `validated`. → Deferred.
- **Environment, not product:** the Host hardcodes `OvermindPaths.DataDirectory` (`~/.overmind`) for the port file and the archive root, so the e2e ran with a temp `HOME` (launcher script in the temp dir sets `HOME`, `Overmind__DatabasePath`, `Overmind__BindUrl`, `OVERMIND_WEB_ROOT`) — every write landed inside `/tmp/overmind-e2e-00610`; the single-instance mutex is user-scoped, not HOME-scoped, so the e2e requires no real Overmind running (checked before boot). Worktree web toolchain needed `npm ci` plus restoring the generated, gitignored `web/next-env.d.ts` before lint/tsc/build would run — nothing tracked changed (`node_modules/`, `.next/`, `out/`, `next-env.d.ts` are gitignored).
</obstacles>
