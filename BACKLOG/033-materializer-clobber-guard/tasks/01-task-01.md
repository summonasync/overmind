<goal>
Materializer stops silently clobbering hand-edited tracked files on the planning path: SyncAsync refuses with a typed error listing every drifted path unless force, and force names each overwritten file in the report warnings.
</goal>

<context>
Real incident behind this: a sub-agent without MCP appended to <obstacles> of a materialized task file on disk; the next force:false materialize regenerated the file from the board and the edits vanished silently. DetectDriftAsync already sees such drift (hash mismatch) — SyncAsync just never consults it before writing.
Key code (read before starting):
- src/Overmind.Infrastructure/Planning/PlanningMaterializer.cs — SyncAsync (lines ~25-66): BuildPlans → GuardOverwrites (untracked only) → WritePlansAsync (writes unconditionally, Refreshes rows). DetectDriftAsync (lines ~68-120): the hash-compare semantics to mirror, including the BACKLOG.md managed-block special case. GuardOverwrites (lines ~324-352): the refuse/force precedent — keep the new guard textually adjacent but logically separate (do NOT reuse its "owned" concept: the new guard keys purely on row-exists + hash mismatch + plan≠disk).
- src/Overmind.Core/Abstractions/MaterializationException.cs — MaterializationFailureKind enum; append the new member LAST (enum-append rule; integer values must not shift).
- src/Overmind.Host/Api/PlanningMaterializationApi.cs — MaterializationError switch (line ~68): OverwriteBlocked → HttpErrors.Conflict (409). The new kind needs an explicit arm BEFORE the 500 fallback.
- src/Overmind.Infrastructure/Planning/PlanningServiceGuard.cs — auto-sync swallow-to-warning; DO NOT touch.
</context>

<scope>
- MaterializationException.cs: new enum member LocalEditssBlocked is WRONG — name it LocalEditsBlocked, appended after IoError; new factory MaterializationException.LocalEdits(IReadOnlyList<string> paths) with a message listing every path plus one hint line: transcribe to the board (planning_upsert_artifact / planning_append_log) or re-run materialize with force.
- PlanningMaterializer.SyncAsync: pre-write guard after BuildPlans (and after GuardOverwrites), before WritePlansAsync. Loss condition per planned file: a row exists for the relative path AND disk content differs from row.Sha256 AND plan content differs from disk content. BACKLOG.md (BacklogIndexRelativePath): compare ManagedBlock-extracted block hash on the disk side vs row.Sha256 (BuildBacklogPlan already stores the block hash in the plan) — hand-written sections outside the markers never trigger. Feature files: whole-file SHA256, ordinal-insensitive compare (DetectDriftAsync precedent).
- Behavior on hits: force:false → collect ALL hits, then a single MaterializationException.LocalEdits throw. force:true → proceed, append one warning per clobbered file: "Overwrote locally modified file: <absolutePath>".
- PlanningMaterializationApi.MaterializationError: LocalEditsBlocked → HttpErrors.Conflict(ex.Message), placed before the catch-all arm.
- Tests (Infrastructure + Api): (a) tracked task file hand-edited, board unchanged → materialize throws LocalEditsBlocked naming the path; API returns 409 with the path in detail; (b) force:true → file regenerated, warning present in report; (c) board mutation via PlanningServiceGuard path while drift exists → succeeds, disk stale (guard unchanged); (d) hand-edit absorbed into the board (artifact body updated to the disk content) → next materialize writes without refusal, row hash heals; (e) BACKLOG.md edit outside managed block → never blocked; inside the block → blocked; (f) locally deleted tracked file → recreated, not blocked; (g) existing untracked-file OverwriteBlocked behavior regression-pinned.
</scope>
