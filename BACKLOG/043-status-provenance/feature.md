# Feature 043 — Status provenance: источник каждого перехода в логе (ui/agent/auto) + предсказуемые и документированные автопереходы

<goal>
Две связанные боли доверия к борде из полевого фидбека: (1) у агентских переходов `logNote` обязателен — и это названо сильнее любой конвенции в CLAUDE.md, — но переходы из UI и автопереходы следа не оставляют вовсе; агент не может отличить действие человека от собственной ошибки и тратит круг уточнений; (2) наблюдаемые автопереходы фич не выводятся из документированных правил и расходятся между собой (четыре фичи уехали в done сами, три висели in inProgress при 100% закрытых задач; поведение done-фичи, получающей новый артефакт, не описано). Статусная система должна быть объяснимой пост-фактум без вопроса человеку.
</goal>

<requirements>
- Каждая смена статуса (feature и artifact) оставляет строку в логе с источником: `ui` / `agent` / `auto-transition` — даже когда человек ничего не написал (служебная строка вместо пустоты).
- Фактические правила автопереходов выверены на живых проектах и задокументированы в onboard/описаниях тулов, включая: done-фича + новый артефакт; условия review→(done) через человека; случай «все задачи done, а фича не в review».
- Расхождение «документировано ≠ наблюдается» трактуется как баг и фиксится в рамках фичи, а не только правкой доков.
</requirements>

<non-goals>
- Расширение допустимых агентских переходов — узость `planning_set_feature_status` (только done/inProgress по явной просьбе юзера) отмечена полевым фидбеком как правильный guard, не трогаем.
- Audit trail правок тел артефактов из UI (только статусы).
- Отмена терминальности done — терминальность подтверждена полем как правильная.
</non-goals>
