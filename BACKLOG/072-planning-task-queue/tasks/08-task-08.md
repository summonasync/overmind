<goal>
Bug (user smoke 2026-09-25): with many features on the board, holding a card in HTML5 drag disables mouse-wheel scrolling — the board cannot be scrolled mid-drag, so a target below the fold is unreachable. Standard fix: edge auto-scroll during drag.
</goal>
<context>
Native HTML5 DnD swallows wheel events while a drag is active in all major browsers — not a regression of the wave but a UX gap of the implementation choice (native DnD per spec decision, no new packages). The board container scrolls (overflow) but nothing scrolls it during a drag. Industry-standard solution: auto-scroll loop — while a card is dragged, scrolling the scroll container when the cursor (dragover position) approaches the container's top/bottom edge, speed proportional to edge proximity, requestAnimationFrame, stopped on drop/dragend.
</context>
<scope>
- web/src/features/planning/components/feature-board.tsx: during an active card drag, track the dragover clientY; when it enters an edge zone (e.g. 64-80px) of the board's scroll container, auto-scroll that container via a rAF loop; stop the loop on drop/dragend/dragleave-cleanup; also handle the case where the scroll container is the window. Keep it small — a helper in lib/ if it cleans the component, no new packages.
- The existing band-scoping/drop logic must be untouched (auto-scroll must not trigger drops or change drop-target resolution — it only scrolls).
</scope>
<anti-scope>
Wheel-event overrides (browser swallowing wheel during native drag is by design); keyboard scroll; touch.
</anti-scope>
<constraints>
No new npm packages; FSD; no comments; English; gates: npm run lint && npx tsc --noEmit && npm run build green; no git commits.
</constraints>
<acceptance-criteria>
- [x] With enough cards to overflow the board, starting a drag and moving the pointer near the container's bottom/top edge scrolls the board in that direction; speed grows closer to the edge; scrolling stops on drop/dragend.
- [x] Drop-target resolution during auto-scroll still lands on the correct card/band.
- [x] Existing gates green (lint/tsc/build); package.json untouched.
- [x] Human confirmation by the user on the real board (they reported it).
