# Feature 035 — Execution queue — хранение порядка движения по фичам

## Что

Персистентная упорядоченная очередь работы над фичами на борде: сущность + UI для хранения и настройки порядка движения (execution order). Сегодня очередь живёт в чате/памяти сессии и умирает между контекстами — агент каждой новой сессии восстанавливает её из memory-файлов или со слов юзера. Должна стать данными на борде: видно человеку в web, читаемо агентами (MCP), редактируемо в обоих местах.

## Почему

- Очередь — единственный крупный кусок workflow-состояния, которого нет на борде: фичи есть, приоритеты (034, P0–P3) есть, а порядок «что за чем едем» — нет.
- Между сессиями очередь теряется/дрейфует: recommendation в memory протухает, юзер повторяет порядок руками.
- 034 даёт грубое ранжирование (4 корзины), но не порядок внутри корзины и не позицию микробатчей; очередь — тонкая настройка поверх.

## Начальный снапшот очереди (на момент создания, 2026-09-20)

033 → 032 → 026 → 029 → 028 → 030 → 007 + микробатч (28) — и 034 после 032 (по слову юзера этой же сессией).

## Открытые вопросы (уровень спеки)

- Сущность: отдельная ordered-коллекция ссылок на фичи vs единый list per project с order index.
- UI: панель очереди на борде (reorder: up/down vs DnD), отражение позиции на карточке фичи.
- Агентская дверь: чтение (onboard/current-task отдаёт очередь?) vs запись (move-in-queue через MCP) — и в какой версии.
- Связь с 034: очередь доминирует над P-рангом при сортировке? Или независимые сущности (queue = явный план, priority = атрибут)?
- Члены очереди: только фичи, или микробатчи/заметки тоже (микробатч — не фича на борде).
